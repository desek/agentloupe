# Scenario: dependency freshness, dry run and the steps that wait

- Goal: the release manager sees, from the shell, that the weekly freshness flow of `docs/specification/dependencies.md` reads the direct dependencies of cargo, of the npm prototype, and of the pinned actions, gives each one class from the real publish dates, plans one `claude -p` update run per stale dependency in the stated order with the run cap, plans one zero-dep assessment per aged dependency with `keep` and no run for each cryptography crate, and writes nothing in a dry run. The hosted dry run of the workflow and the first real run wait.
- Surface: the shell with `.agents/scripts/deps.freshness.sh` on the checkout, the real registries (crates.io with the `User-Agent` of the project, the npm registry, the GitHub API through the real `gh` login of the owner, read only), a recording wrapper of `gh` and a sentinel `claude` first on `PATH`; the pull request on GitHub and its verdict run, read with `gh`.
- Success condition: (1) the scan of the source tree gives the classes of the baseline of CR-0027 (5 stale crates; 8 aged crates with `hmac` behind; `chrono`, `getrandom`, `bytes`, `serde`, and `toml` fresh), 13 of 13 latest versions of the baseline table, 4 npm lines and 8 action lines; (2) `update --dry-run` plans `hmac`, `aes-gcm`, `sha2`, `rusqlite` and marks `reqwest` and `tokio-tungstenite` with `run_cap`; (3) `assess --dry-run` plans `keep` with no run for `hmac` and `subtle` and one run for each other aged crate; (4) 0 `claude` calls, 0 `gh` calls other than GET, an unchanged tree and HEAD, and no new branch, pull request, or issue; (5) each scan takes at most 120 seconds; (6) the shell tests pass in the test stage, the full local verdict exits 0, and the hosted check `verdict` of the pull request is green; (7) `gitleaks` and the pattern search find 0 credentials in the dry run log.
- Who: "agent" steps run from the coding agent with `gh` and the shell; "owner" steps change the visibility or create a secret.

## Preconditions

- The verdict workflow `.github/workflows/verdict.yml` is active on `desek/agentloupe`; the repository is private.
- The shell of the agent holds no `GH_TOKEN`, no `RELEASE_TOKEN`, and no `CLAUDE_CODE_OAUTH_TOKEN`; `gh` is logged in as the owner.
- `curl`, `gh`, `git`, `jq`, and `perl` are installed. A dry run needs no `claude`, `cargo`, or `corepack`.
- A wrapper directory first on `PATH` holds `gh` (it appends its arguments to a file, then runs the real binary) and `claude` (it appends its arguments to a file and exits 99).
