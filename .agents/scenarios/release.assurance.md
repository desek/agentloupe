# Scenario: supply chain assurance, private parts

- Goal: the parts of `docs/cr/CR-0025-supply-chain-assurance.md` that the specification states for a private repository work from the seat of the release manager: the release binary builds with the release profile and is smaller with no slower start; each archive and each platform image gets a CycloneDX SBOM file with its checksum file, which `release.check.sh` verifies; a squash merge or a new commit over a proved tree reuses the hosted verdict; and the advisory response plans its actions on a seeded advisory with no write. The steps that need the public repository wait, in the order of the section "Steps that wait for the public repository".
- Surface: the shell with `.agents/scripts/release.build.sh`, `release.sbom.sh`, `release.check.sh`, `advisory.respond.sh`, and `pipeline.verdict.sh`; `cargo nextest`; Docker for the Linux builds and checks; the pull request on GitHub and its verdict runs, read with `gh`.
- Success condition: each agent step below passes in one run; every threshold of the Part 4 rows of `docs/specification/release.md` (Release build profile, Measured values) holds; the reuse run reports `decision: hit` with a tree equal to `git rev-parse <commit>^{tree}` and ends in at most 3 minutes; the seeded dry run plans 1 draft, 1 note, and 1 issue with 0 write calls; no tag, release, image, or advisory exists on GitHub afterwards.
- Who: "agent" steps run from the coding agent with `gh` and the shell; "owner" steps change the visibility, merge the release pull request, or create a secret.
