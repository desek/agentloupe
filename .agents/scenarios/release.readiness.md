# Scenario: public release readiness

- Goal: the file changes of `docs/cr/CR-0024-public-release-readiness.md` are on `main`, the repository settings script plans the settings on the private repository and writes nothing, and the outward steps (the switch to public, the settings apply, the merge of the release pull request) wait for the owner in the order of `docs/specification/release.md`, section "First release".
- Surface: the GitHub pull requests, the repository settings, the `gh` CLI, `.agents/scripts/repo.settings.sh`, `.agents/scripts/deps.deny.sh`, `.agents/scripts/release.notices.sh`, and `.agents/scripts/pipeline.verdict.sh`.
- Success condition: each agent step below passes in one run; the settings script makes 0 writes on the private repository in each mode; the release pull request stays open with the proposal `0.1.0`; no tag exists.
- Who: "agent" steps run from the coding agent with `gh` and the shell; "owner" steps change the visibility, apply the repository settings, or merge the release pull request, and only the owner runs them.

## Steps

3. Agent: in a scratch copy, remove one license from one list, then from both lists: `deps.deny.sh` and `release.notices.sh` exit 1 and name the license, and the crate with it. 4. 5. Agent: run the full local verdict `.agents/scripts/pipeline.verdict.sh` and check exit code 0.
6. Agent: push a branch, open the pull request `feat(release): Public release readiness (CR-0024)`, watch the verdict workflow with `gh run watch`, and squash merge it under that title when it is green.
7. Agent: check that the verdict workflow passed on `main`, that release-please updated the release pull request with no `GITHUB_TOKEN` permission, that the release pull request is open, still proposes `0.1.0`, and changes only `CHANGELOG.md`, and that `release-please-config.json` still holds `release-as`.
8. Agent: delete the stale remote branch: `git push origin --delete feat/cr-0022-release`. Check `git ls-remote --heads origin`.
9. Agent, private: `repo.settings.sh --dry-run` and `--dry-run --human`. Check: both rulesets, secret scanning, and private vulnerability reporting are `unavailable` with the reason; the merge settings, the actions policy, and the Dependabot alerts are `planned`; the last line gives 0 writes; exit code 0.
10. Agent, private: `repo.settings.sh` and `repo.settings.sh --check`. Check exit code 5, an error that names the visibility, and the same values of step 1 afterwards.
11. Owner: `gh repo edit desek/agentloupe --visibility public --accept-visibility-change-consequences`. Agent: `gh repo view desek/agentloupe --json visibility` prints `PUBLIC`.
12. Owner: `.agents/scripts/repo.settings.sh --dry-run`, then `.agents/scripts/repo.settings.sh`, then `.agents/scripts/repo.settings.sh --check`. Check: no line is `unavailable`; each setting of the dry run is `applied`; a second run gives `writes: 0`; `--check` exits 0. Parameters P1 (the SHA pin policy), P4 (the app of the check `verdict`), and P2 (the community profile counts the Markdown issue templates) are checked here.
13. Agent: the remaining steps 10 to 15 of `docs/cr/CR-0024-public-release-readiness.md`, section "Model-Based Testing": the `gh api` checks of each setting, the drift test, the scratch pull request with a format error, the community profile 100, and the secret scanning alerts.
14. Owner: squash merge the release pull request `chore(release): release 0.1.0` only after step 12 ends with `--check` exit 0. Agent: steps 10 to 17 of `.agents/scenarios/release.first.md`, with the four `notices` lines of `release.check.sh --version 0.1.0`; parameter P5 (the tag of release-please under the tag ruleset) is checked here.
15. Owner, before the owner's install runs the new version: add `LOUPE_TZ=Europe/Stockholm` to the local `.env`, so the days keep their cut (the default is now `UTC`).
